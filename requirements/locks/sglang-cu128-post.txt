# Installed AFTER sglang-cu128.txt, with --no-build-isolation.
#
# Nothing here can go in the main lock, for two different reasons:
#
#   nvidia-cudnn-cu12  A deliberate override. torch 2.9.1 pins 9.10.2.21 while
#                      SGLang refuses to start on torch 2.9.x below cuDNN 9.15 and
#                      says so itself ("CRITICAL WARNING: PyTorch 2.9.1 & CuDNN
#                      Compatibility Issue Detected" -- a Conv3d bug,
#                      https://github.com/pytorch/pytorch/issues/168167). In one
#                      resolution pip calls that ResolutionImpossible; applied
#                      after, it warns and the newer cuDNN wins. The warning is
#                      the expected outcome, not a problem to fix.
#
#   flash-attn         A build-order constraint, not a version conflict. There is
#                      no wheel for this torch, so pip builds from source -- and
#                      under build isolation that build has no torch to compile
#                      against, failing as "Failed to build 'flash-attn' when
#                      getting requirements to build wheel". It needs the torch
#                      from the main lock already present, hence a second pass
#                      with --no-build-isolation.
#
#                      verl hardcodes attn_implementation="flash_attention_2" when
#                      it builds the critic's value head, so something has to
#                      answer for it.

#   trl                A third kind: a stale upper bound. trl 0.9.6 declares
#                      numpy<2.0.0 while verl 0.9.0 declares numpy>=2.0.0, so the
#                      two cannot share a resolution at all -- pip reports
#                      ResolutionImpossible naming numpy. The reference deployment
#                      runs trl 0.9.6 against numpy 2.2.6, so the bound is stale
#                      rather than real; installing it after lets pip warn and
#                      keep numpy 2.x.
#
#                      Only the critic's value head needs trl
#                      (AutoModelForCausalLMWithValueHead), which is why a stale
#                      bound in it can be overridden without touching training.

nvidia-cudnn-cu12==9.16.0.29
flash-attn==2.8.3
trl==0.9.6
