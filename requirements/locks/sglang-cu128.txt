# Verified training stack: SGLang 0.5.8, CUDA 12.8.
#
# Exercised on A100-SXM4-80GB and H200-141GB; nothing here is card-specific.
#
# This is the default selected by `scripts/install.sh`. The Transformers pin is
# inside verl's supported SGLang range: >=5.5.3, !=5.6.0, <5.11.
#
#   bash scripts/install_sglang.sh
#
# Why the versions are what they are, where it is not obvious:
#
#   torch 2.9.1        what sglang 0.5.8 pins.
#   transformers 5.10  supports the newer model families while staying inside
#                      the range declared by verl for SGLang 0.5.8.
#   nvidia-cudnn 9.16  in the -post file, applied after this one. sglang refuses
#                      to start below 9.15 on torch 2.9.1 (pytorch/pytorch#168167,
#                      a Conv3d bug) while torch pins 9.10.2.21. Installed in the
#                      same pass that is a hard ResolutionImpossible; installed
#                      after, pip warns and the newer cuDNN wins, which is correct.
#   trl 0.9.6          verl's critic loads AutoModelForCausalLMWithValueHead from
#                      trl. Newer trl (>=0.27) is required *only* on the 5.x
#                      stack, where its __init__ hard-imports vllm.
#   flashinfer 0.6.1   the pair sglang 0.5.8 was built against. flashinfer-python
#                      and flashinfer-cubin must match exactly or the import
#                      refuses. Take care: a bare `pip install flashinfer-python`
#                      pulls a cu130 torch over a cu128 one.
